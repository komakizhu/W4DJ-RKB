> **协议更正（2026-08-25）：** 本文原先使用的 `.w4djcrate` v1 只是历史规划格式，已被当前主会话确认的全新 `.w4dj` v2 最小格式取代。v1 不迁移、不兼容读取；现行字段和导入规则以 `docs/superpowers/plans/2026-08-25-minimal-w4dj-playlist-format.md` 为准。

本规划的目标是让 W4DJ 接入 DJ Crate Digger Skill 导出的 `.w4dj` 歌单文件，并把“歌单整理、网易云手机导入、下载回收、文件补齐、Rekordbox 准备”串成一条本地工作流。

## 目标输入格式

`.w4dj` 为 UTF-8 JSON。当前共享结构固定为全新的 v2 最小格式：

```json
{
  "format": "w4dj",
  "format_version": 2,
  "export_id": "...",
  "playlist": {
    "name": "..."
  },
  "tracks": [
    {
      "position": 1,
      "title": "...",
      "artist_display": "...",
      "netease_track_id": "..."
    }
  ]
}
```

`tracks[].position` 是歌单顺序；`netease_track_id` 必须是字符串，缺失时省略。`dedupe_key` 由 W4DJ 在内存中生成，不属于交换文件；W4DJ 对最终文件名、路径清理、重名处理和永久目录布局拥有最终权威。

## 计划中的用户流程

建议采用单一状态流：

```text
导入歌单 → 准备 Rekordbox → 手机导入网易云 → 等待下载 → 扫描并补齐 → 完成
```

1. 用户导入 `.w4dj`。
2. W4DJ 扫描已有曲库，并为每首歌显示“已有、待获取、版本冲突、无法匹配”等状态。
3. 对缺失曲目生成合法、可播放、明确标记为 pending 的短 MP3 占位文件。
4. W4DJ 执行跨平台文件名清理、顺序编号、重名处理和永久目录布局，并生成使用相对路径的 Rekordbox M3U8。
5. W4DJ 启动只允许局域网访问的临时手机页面。二维码只编码带随机令牌的临时 URL，不把完整歌单直接塞进二维码。
6. iPhone 与电脑处于同一 Wi-Fi 后，用户扫码查看歌单名、总数和分段复制按钮。每段默认 15 首，每行复制“歌名 艺人”，保持原始顺序。
7. 用户在网易云 iOS 中使用文字导入，创建歌单并下载全部曲目。
8. W4DJ 扫描或监听网易云下载目录及统一下载收件箱，自动匹配已下载文件，处理 NCM 和常见音频格式，完成命名后用真实音频安全替换同一路径的 pending 占位文件。
9. W4DJ 对照交接记录核验歌曲名、歌手、专辑和版本。专辑不同但可能是同一录音时标记“需确认”；Remix、Edit、Live 等版本差异视为冲突，不自动接受。
10. 补齐后提示用户让 Rekordbox 重新加载标签并重新分析。必须实测占位文件被真实文件覆盖后，时长、波形、BPM 和调是否能正确刷新。
11. 关闭窗口或结束会话后，手机页面和二维码令牌失效。

## 匹配与替换安全边界

- 本地已经存在的歌曲优先复用，但不得因为标题相似就替换为错误版本。
- Remix、Edit、Live 等版本信息必须参与冲突判断；不确定时保留占位并要求用户确认。
- 真实音频替换 pending 文件时必须使用临时文件和安全提交，失败不得留下半成品，也不得破坏原有可用文件。
- 替换完成后保留匹配证据和冲突记录，便于用户复核。
- 专辑精确匹配目前尚未确认，正式实现前需要明确“专辑不同但录音相同”的判定和展示方式。

## 临时手机页面与隐私边界

第一版只做本地局域网能力：不上传云端、不保存网易云账号或 Cookie、不依赖非官方网易云 API，也不把完整歌单放进二维码。实现时需要确认：

- HTTP 服务只绑定局域网可用地址，不默认暴露到公网。
- URL 令牌具有足够随机性，并带有会话过期机制。
- 关闭窗口、结束会话和应用退出都会使页面失效。
- 端口被占用、不同 Wi-Fi、局域网不可达、二维码过期时都有明确降级提示。
- 不在日志、报告或 URL 中泄露不必要的本地路径、账号信息或完整歌单数据。

## Rekordbox 产物

M3U8 使用相对路径，最终每一行都必须对应一个实际音频文件。占位文件的作用是先让 Rekordbox 建立合法条目；真实文件覆盖后，用户需要按提示重新加载标签并重新分析。不能把不存在的路径当作可靠的 Rekordbox Missing 壳。

需要验证：

- Mac 和 Windows 的相对路径包都能被 Rekordbox 使用。
- 10、20、50 首歌时 M3U8 顺序与实际文件逐条一致。
- pending 占位导入后，真实文件原路径覆盖不会留下错误时长、波形、BPM 或调。
- Windows 的占位、替换和 Rekordbox 刷新行为仍需实测。

## 已知事实与未决事项

已知：Mac 上已经验证“合法短 MP3 占位文件 + 相对路径 M3U8”这条路线可行；网易云 iOS 的六首歌曲文字导入已经成功，但专辑精确约束尚未确认。

实现前仍需确认：`.w4dj` v2 之外的占位音频固定来源与时长、永久目录布局、编号规则、监听目录的授权方式、版本冲突的最终 UI、手机页面的默认分段数是否固定为 15、Windows 局域网和 Rekordbox 的实际表现，以及真实文件覆盖后是否需要额外触发 Rekordbox 刷新动作。

Spotify 和 Apple Music 官方 API 只保留为未来可选适配器，不属于 MVP；第一版不加入这些适配器。

- 10/20/50 首歌：二维码页面、分段复制、顺序保持正确。
- iOS 文字导入成功，并记录错配、漏配和版本冲突。
- Mac/Windows 相对路径包可用。
- 占位 MP3 可被 Rekordbox 导入，真实文件能安全覆盖同一路径。

- 局域网不可达、端口冲突、不同 Wi-Fi、令牌过期均有明确提示。
- 最终 M3U8 与实际音频逐条一致。

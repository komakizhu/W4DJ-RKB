# Essentia 预训练模型网页下载与本地导入设计

日期：2026-08-18<br>
产品版本：W4DJ 3.2.0 beta-3（`3.2.0-beta.3`）

> 实施补充：用户随后批准把约 3.5 MB 的模型集与 TensorFlow.js 直接内置。当前实现启动时从 App 资源自动补齐模型；普通界面已移除恢复、官方下载、导入模型按钮和模型拖入入口，本文后续能力仅作为 Rust 兼容维护路径记录。

## 目标

在现有 Essentia 预训练模型区域增加官方网页下载入口和本地模型导入能力。用户既可以点击按钮选择模型文件，也可以把模型拖到应用窗口任意位置。模型拖入时显示全窗口模糊遮罩；歌曲文件或文件夹继续使用既有任务槽拖放逻辑，不改变转换来源选择行为。

## 范围

本功能支持以下输入：

- Essentia 官方 MusiCNN TensorFlow.js ZIP 包；
- 一次选择或拖入的一个或多个 TensorFlow.js `model.json` 与 `.bin` 权重文件；
- 通过系统浏览器打开 Essentia 官方模型目录。

本功能不支持任意 TensorFlow、PyTorch、ONNX 或用户自训练模型，不修改分析算法、模型 ID、分类标签和置信度规则，也不自动把导入文件上传到网络。

## 用户界面

现有“Essentia 预训练模型”设置区增加两个按钮：

- “官网下载”：用系统默认浏览器打开 `https://essentia.upf.edu/models/`；
- “导入模型”：打开允许多选的文件选择器，接受 ZIP、JSON 和 BIN。

模型候选文件进入窗口时，整个应用显示带背景模糊的遮罩，中央文案为“松开以导入 Essentia 模型”。拖离窗口后遮罩消失；导入期间遮罩改为“正在验证并导入模型…”，防止重复操作。

音频文件或文件夹进入窗口时不显示模型遮罩，继续使用现有任务 1/2 来源和输出区域的局部高亮与投放行为。一次拖入同时含有模型候选和歌曲/文件夹时不执行任何导入，提示用户把模型和歌曲分开拖入。

导入完成后立即刷新模型状态。完整模型集合显示现有“已下载”状态；部分成功时显示成功数量和仍缺失的能力；失败时显示具体原因，已有模型状态保持不变。

## 拖放分类

前端在原生 Tauri `DragDropEvent` 的 `enter`/`over` 阶段根据全部路径进行快速分类：

- 全部路径都是 `.zip`、`.json` 或 `.bin` 时视为模型候选，显示全窗口遮罩；
- 路径含支持的歌曲格式，或不是模型候选扩展名时，交给既有歌曲/文件夹投放逻辑；
- 模型候选与其他路径混合时视为混合投放，松开后提示分开拖入。

扩展名分类只决定界面和路由，不代表模型有效。真正的格式识别和安全校验由 Rust 后端完成。浏览器测试环境无法稳定取得本地路径时，保留“导入模型”按钮作为确定性入口。

## 后端接口与导入流程

新增 Tauri 命令接收路径数组并返回结构化导入结果，结果至少包含安装成功的模型 ID、忽略项、缺失项、更新后的 `EssentiaModelStatus` 和用户可读消息。命令只接受本机已有文件路径，不接受 URL 或前端提供的目标路径。

导入按以下顺序执行：

1. 校验输入数量、扩展名、文件类型和单文件/总大小上限；目录和符号链接不作为模型文件导入。
2. ZIP 只读取普通文件条目，同时兼容 Essentia 官方 MusiCNN 包当前存在的非标准本地条目头；拒绝绝对路径、父目录跳转、嵌套归档、重复冲突条目和超出解压上限的内容。
3. 解析 `model.json`，读取其 TensorFlow.js `weightsManifest`，确定所需权重文件并与同批 BIN 或 ZIP 条目配对。
4. 根据已知 Essentia 模型规格、官方父目录/文件命名、模型结构、输入输出形状和类别数据共同识别目标模型。文件名只作为身份候选，结构校验必须同时通过；被重命名且无法唯一判断身份的分类头拒绝安装，不进行猜测。
5. 将每个识别出的完整模型写入应用模型目录内的临时文件，重新读取校验后再原子替换该模型对应的 JSON/BIN。
6. 一个批次中各模型独立安装：有效模型可以成功，未知或不完整模型被报告；任何失败模型都不得覆盖它原先可用的版本。
7. 重新计算并返回模型状态。

若同一批次提供同一模型的多个冲突版本，该模型拒绝导入并保留旧版本。ZIP 与外部 JSON/BIN 同时提供同一模型时也按冲突处理，不静默选择其中之一。

## 安全与故障处理

导入过程不持有全局转换状态锁，不启动转换或分析，也不写转换历史。只写应用自己的 Essentia 模型目录。所有错误消息隐藏模型目录的完整本机路径，只显示用户选择的文件名、模型 ID 和校验原因。

文件选择取消是无操作；重复拖放在导入进行中被拒绝。窗口关闭不会留下目标名临时文件；下次启动可忽略或清理由本导入流程命名的临时文件。网页打开失败显示系统浏览器调用错误，不改模型状态。

## 测试与验收

Rust 测试覆盖：

- 官方 MusiCNN ZIP 成功识别和安装；
- 成组 JSON/BIN 成功安装一个或多个已知模型；
- JSON 缺权重、未知模型、空文件、错误扩展名和冲突模型被拒绝；
- ZIP 目录穿越、绝对路径、嵌套归档、重复条目和解压大小超限被拒绝；
- 失败不覆盖已有模型，成功后状态立即更新；
- 返回 DTO 使用 camelCase。

前端测试覆盖：

- “官网下载”调用系统浏览器并使用固定官方 URL；
- “导入模型”允许多选并调用导入命令；
- 模型候选拖入显示全窗口模糊遮罩，拖离后清除；
- 歌曲和文件夹仍走既有任务槽逻辑且不显示模型遮罩；
- 混合投放被拒绝；
- 导入成功、部分成功和失败状态正确渲染，失败不污染任务槽状态。

最终运行前端测试与生产构建、Tauri 测试与 check、Rust 全量测试、格式检查、Clippy 和 `git diff --check`。真实模型导入使用从 Essentia 官方页面下载的 MusiCNN ZIP 完成应用级验收；若当前网络或 GUI 环境不可用，记录未执行原因和人工步骤，不以合成测试替代真实验收。

## 非目标

不新增模型在线市场、版本自动更新、模型签名、hash baseline、冻结 contract 或发布 gate；不 commit、push、merge、创建 Release 或发布制品。

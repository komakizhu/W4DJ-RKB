# W4DJ 全局扫描与 FFmpeg 并发设计

日期：2026-08-23

状态：代码与本地自动化验收完成；真实 M1 转换吞吐和 GUI 取消仍待环境验收

## 目标

W4DJ 在“高级选项”中提供一个持久化的全局并发设置。设置使用横向滑块和数字输入框，默认值为 `2`，允许 `1–10` 的任意整数。该设置同时控制扫描阶段的并发工作数量和歌曲转换阶段的最大并发歌曲数量。两个任务槽共享同一个全局上限，不能分别获得完整额度。

并发值在扫描或转换任务启动时形成不可变快照。用户在任务运行期间修改设置，只影响下一次扫描或转换，不调整当前任务的 worker 数量。

## 范围

本功能影响普通转换、无损转换和增强模式下的扫描与歌曲转换。增强分析使用的 Essentia、TensorFlow 和分析 Worker 并发不受该设置控制，继续遵循现有单曲隔离和资源生命周期约束。

本功能不改变输出格式、命名规则、冲突策略、分析模型、Task 6–13 接口含义或版本号，也不新增发布门禁、baseline、hash 或冻结 contract。

## 用户界面

“高级选项”增加“扫描与 FFmpeg 并发”设置。控件由一个 `min=1`、`max=10`、`step=1` 的横向滑块和一个同范围的数字输入框组成，并显示当前数值。两个控件双向同步：拖动滑块更新数字输入，编辑数字输入更新滑块。

空值、非整数和越界输入在提交时规范化：空值恢复最近合法值，非整数取最接近整数，低于 `1` 取 `1`，高于 `10` 取 `10`。默认值为 `2`。设置始终在“高级选项”中可见，并同时影响普通模式和增强模式。

任务运行期间允许修改控件，但界面明确说明“下次扫描或转换生效”。当前任务继续显示其启动时使用的并发值，避免用户误以为 worker 会动态增减。

## 偏好与状态接口

`AppPreferences` 新增向后兼容字段 `concurrency_limit`，Serde 缺省函数返回 `2`。所有偏好读取、旧格式迁移、桌面状态恢复和普通偏好保存都必须保留该字段。进入运行态前统一调用规范化函数，将值限制在 `1..=10`。

`DesktopState` 和前端 `AppViewState` 暴露对应的 `concurrency_limit` / `concurrencyLimit`。设置变更沿用现有偏好更新与持久化路径，不创建第二套配置文件。扫描和转换命令从桌面状态复制并发快照，之后不再读取实时偏好。

## 全局并发模型

应用使用一个全局并发预算抽象，负责维护固定数量的 permit。扫描和转换分别拥有自己的任务协调器，但都使用任务启动时的同一个限制语义。两个任务槽提交到同一阶段的全局工作队列，因此任意时刻活跃的扫描工作或歌曲转换工作不会超过快照值。

扫描和转换在当前产品流程中通常不会重叠；并发预算仍设计为应用级组件，以保证未来出现阶段重叠时不会把两个上限相加。并发控制不得通过每文件无限 `thread::spawn` 实现，应使用固定 worker、受限队列和明确的关闭流程。

## 扫描阶段

扫描协调器负责目录枚举、取消检查、进度总数和结果合并。目录枚举可以按输入根目录并行，但单个目录树的迭代保持可取消。枚举出的支持文件按稳定索引提交给固定大小的扫描 worker 队列。

worker 负责可并行的文件级工作，包括读取文件元数据、缓存命中判断、歌曲名推导和现有扫描链路要求的文件探测。worker 不直接修改共享的扫描缓存、预览 `HashMap` 或 UI 状态，而是返回包含槽位、阶段、稳定索引、路径、结果和缓存更新的数据对象。

协调器串行合并 worker 结果，保持现有文件优先级、重复歌曲选择、跨槽去重、缓存写入和预览语义。最终候选顺序使用稳定索引或现有排序规则恢复，不能因为完成顺序不同而使同一输入产生不稳定预览。

进度的 `processed` 在一个文件结果完成并被协调器接收后递增。`currentFile` 显示最近启动或最近完成的文件，并额外显示当前活跃工作数。取消后停止提交新文件，允许正在执行的可中断工作尽快退出；取消终态只能发送一次。

## 转换阶段

确认转换后，两个任务槽的候选歌曲以槽位和原始顺序标记，提交给同一个全局转换队列。固定 worker 数等于任务启动时的并发快照，但不超过待处理歌曲数。

每个 worker 独立执行一首歌曲的 NCM 解密、FFmpeg 转换、元数据处理和逐曲输出事务。现有临时文件、输出校验、备份恢复、冲突保护和安全提交语义必须保留。目标路径协调在任务入队前或提交前完成，禁止两个 worker 同时写入同一个目标路径。

FFmpeg 从阻塞式 `Command::status()` 改为受管理的 `Command::spawn()`。协调器登记活跃子进程，使取消可以停止派发新歌曲并终止正在运行的 FFmpeg。终止后清理未提交临时输出，不覆盖原有安全文件。已经完成最终提交的歌曲保持成功结果。

worker 只返回逐曲结果，不直接写 UI、历史集合或共享桌面状态。协调器串行执行 `TaskController` 完成计数、失败分类、日志、历史、W4DJ SQLite 登记和事件发送，避免并发回调竞态。不同槽位可以交错完成，但每条结果必须归属正确槽位。

## 进度和取消

每个槽位继续维护自己的总数、完成数、失败数和当前文件。全局协调器同时维护活跃工作数量。界面显示最近活动文件及“正在并发处理 N 首”；不要求为每个活跃文件增加独立进度条。

暂停或取消首先阻止新工作进入队列。暂停不强制杀死已经开始的单曲；活跃单曲完成后 worker 等待恢复。取消终止活跃 FFmpeg，并要求 NCM/元数据阶段在安全检查点观察取消。取消、错误和成功均必须释放 worker、channel、permit 和子进程句柄。

修改并发控件不会影响正在运行的协调器。下一次启动时读取新的规范化值并创建新的 worker 集合。

## 错误处理

单曲扫描或转换失败只生成该歌曲的失败结果，不取消其他队列项目；只有无法建立队列、无法创建必要 worker、扫描缓存无法安全提交或协调器自身失效时才终止整个阶段。

worker panic 必须转换为可报告的任务错误，并释放占用的 permit。FFmpeg 启动失败、非零退出和取消终止使用不同错误类别，避免把用户取消记录成文件损坏。

偏好保存失败沿用现有错误反馈，当前内存中的合法设置仍可用于下一次任务，但重新启动后使用最后成功保存的值。

## 验收标准

以下项目全部满足后，本功能才可以记录为实现完成：

1. 首次读取旧偏好或不存在偏好文件时，界面和后端并发值均为 `2`。用户可以通过滑块或数字输入选择 `1–10` 的任意整数；两个控件始终显示同一个规范化值。重新启动 App 后恢复最后一次成功保存的值。
2. 输入 `0`、负数、超过 `10` 的数字、小数、空字符串或非数字内容不会把非法值传入后端。最终持久化和任务启动使用的值始终是 `1..=10` 的整数。
3. 扫描或转换启动后修改并发设置，当前任务的最大活跃工作数保持启动快照不变；下一次任务使用修改后的值。当前任务的进度、取消状态和结果不因设置变化而重置。
4. 对包含不少于 `2 × 并发值` 个文件的扫描样本，仪表或测试探针观测到的活跃文件级扫描工作数从不超过配置值；配置值大于 `1` 时必须实际观测到至少两个扫描工作重叠，不能只是保存设置但仍串行执行。
5. 对包含不少于 `2 × 并发值` 首需 FFmpeg 转换歌曲的批次，活跃 FFmpeg 子进程数从不超过配置值；配置值大于 `1` 时必须实际观测到至少两个 FFmpeg 转换重叠。
6. 两个任务槽同时有待转换歌曲时，两个槽合计的活跃 FFmpeg 数不超过同一个全局上限。例如设置为 `3` 时，全应用最多存在 `3` 个受 W4DJ 管理的转换子进程，而不是每个槽各 `3` 个。两个槽的完成数、失败数、当前文件和历史归属必须正确。
7. 设置为 `1` 时，扫描和转换行为退化为严格串行；输出候选、冲突选择、文件名、元数据和最终文件内容语义与改造前一致。设置为 `10` 且任务足够多时，上限可以达到 `10`，但不得创建超过 `10` 个活跃工作。
8. 用户取消转换后不再派发新歌曲。所有由该批次启动且尚未完成的 FFmpeg 子进程在人工验收中应于 `5` 秒内退出；未提交临时输出被清理，已完成安全提交的歌曲保留，原有目标文件不被破坏。取消不得被记录为文件损坏。
9. 任意一首扫描或转换失败不会阻止其他歌曲继续执行。worker panic、FFmpeg 启动失败和非零退出均能归入对应歌曲并释放并发额度，批次不会永久停留在运行状态。
10. 同一输入、同一偏好分别以并发 `1` 和并发 `2` 执行时，扫描候选集合、跨槽去重结果和成功输出集合一致；允许完成顺序和耗时不同，不允许出现重复写入、遗漏歌曲或目标路径冲突。
11. 在 M1 Max 真实批次中，以至少 `10` 首需要实际 FFmpeg 转换的歌曲比较并发 `1` 与并发 `2`。并发 `2` 的总转换时间必须低于并发 `1`，目标提升至少 `25%`；若未达到，必须记录 CPU、磁盘、源格式和瓶颈，不能宣称加速验收通过。
12. 默认并发 `2` 连续完成单槽、双槽、普通模式、无损模式和增强模式转换时，App 可继续响应按钮和滚动，不闪退、不遗留 FFmpeg 子进程。增强分析仍保持原有并发策略，不能因本设置升到 `3–10` 个分析 Worker。

## 测试与验收

Rust 测试覆盖：默认值、旧偏好迁移、非法值规范化、偏好往返；单槽和双槽共享上限；活跃扫描工作不超过限制；活跃歌曲转换不超过限制；运行中修改只影响下一批；稳定结果顺序；取消停止派发并终止子进程；单曲失败不影响其他歌曲；临时输出与事务安全保持不变。

前端测试覆盖：滑块与数字输入双向同步；默认值和 `1–10` 边界；空值和非法输入恢复；中英文文案；运行中显示“下次任务生效”；重新加载恢复偏好；设置变化不触发当前进度重置。

自动验证至少运行现有前端完整测试、Vite 构建、Rust 全部测试、Tauri 测试、格式检查、Cargo check、严格 Clippy 和 `git diff --check`。

真实验收使用单槽和双槽歌曲批次分别测试并发 `1`、`2`、`3` 和 `10`。记录活跃 FFmpeg 数、扫描活跃工作数、完成时间、CPU、内存、取消响应和输出一致性。M1 8GB 的产品默认值保持 `2`；高并发只是用户主动选择，不根据硬件自动上调。

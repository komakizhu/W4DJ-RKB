# W4DJ 快速增量扫描实施计划

**Goal:** 将扫描收敛为一次文件系统快照，并以 W4DJ 私有 SQLite 记录成功提交输出，避免二次扫描重复查库和读取音频标签。

**Architecture:** `scan-cache.json` 只缓存源文件名推导结果；W4DJ SQLite 的 `w4dj_track_meta` 保存已安全提交的源到输出映射及指纹。网易云索引准备和逐曲完整元数据恢复延迟到转换阶段，扫描只处理路径、文件名、大小和 mtime。

**Constraints:** 保留现有冲突策略、临时文件安全提交、取消、双任务槽和转换后增强分析；不提交、不推送、不发布；缓存或数据库错误只能降级，不能覆盖可用输出。

## Milestones

1. 一次遍历快照与 scan-cache v3：命中缓存先于名称推导，移除扫描预遍历、标签读取和 Metadata 阶段。
2. W4DJ 已提交输出映射：schema v3 迁移、批量读取、提交后事务更新和源指纹验证。
3. 转换阶段网易云准备/逐曲查询：扫描不构造 resolver，转换后台准备索引后逐曲补全元数据。
4. 前端复用/增量进度与回归测试：任务卡显示计数，完成 Rust/Tauri/前端验证和本机 1000 首基准。
